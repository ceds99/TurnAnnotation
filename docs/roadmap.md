# 实施顺序

当前只完成项目定义、研究与案例设计；以下实现任务均未完成。

## M0：原生能力验证

在支持版本的 Claude Code 中验证消息读取、选区、侧栏、输入合并和一次普通 user message 提交。逐项执行 [接入通过条件](native-integration.md)。

若任意选区不开放，先记录事实并比较原生段落入口、宿主贡献或其他官方扩展路径；不以 UI 抓取绕过。

## M1：反馈组装核心

实现与宿主无关的确定性组装器，覆盖零批注、多个批注、重复短语、代码块、中英文/Unicode、自由输入、历史隔离。与 B 组高质量手工反馈比较产出。

完成契约验证后再接入本地历史与真实 UI，避免界面细节影响组装实验。

## M2：一个真实可用的原生流程

完成选区到批注、预览与普通输入合并、单次发送、失败草稿保留、下一轮不重发、重启后回看。无额外模型调用；遵守原生运行/排队行为。

安装与卸载应只影响本插件，避免修改其他工具配置。暂不接入第二个 harness。

## M3：可复现的测评 pilot

实现原子请求评分和真实产物断言，采集真实用量，校验 Promptfoo adapter 与原生消息语义。运行 A/B/C pilot，确定任务分布、评分可靠性与正式实验样本量。

## M4：冻结协议并执行正式实验

锁定主比较、模型/宿主版本、质量界值、token 上限、样本量、评分器、停止与错误处理规则。输出可复现报告、置信区间和失败样例；允许证据不足或未通过的结果。

## M5：再决定 Codex 适配

以已验证的组装核心、存档契约和测评方法为基础，核查 Codex 原生界面的可用扩展点。不要把 app-server 自定义 UI 标成原生桌面插件。
