# 产品定义

状态：2026-10-09 用户确认。技术实现形式仍待验证。

## 目标

在 Codex / Claude Code 等原生产品中，为回复提供逐段批注；批量组装反馈并与输入框中其他内容一起发送，减少手工组织引用与对应关系的工作。

项目关注“想法 → harness 局部修改 → 扎实的测评实验”。不以难以被原生功能替代作为立项前提，也不提前承诺节省 token 或提高回答质量。

## 用户已确认的边界

- 批注是普通用户消息的编辑方式，没有额外指令层级。
- 界面中的高亮、卡片、位置和历史记录不进入模型上下文。
- 只有本次组装后的文字成为本次 user message 的一部分。
- 每轮批注保留供日后回看，不在下一轮自动重发，不自动转成规则、memory、skills 或项目指令。
- 已发出的 user message 按原生客户端的普通历史、缓存和压缩机制处理；不承诺发送过的内容立即从上下文消失。
- 批注不触发独立问答。完成全部批注后，用户仍可输入任意补充问题，再一起发送。
- 沿用原生回复与执行行为，不增加 agent 声称完成、自动关闭、用户验收等工单流程。
- 实现应简单、真实可用、可开源，不依赖 UI 抓取或模型请求代理。
- 本阶段只定义固定任务和固定修改意图的模型/产物实验。

## 第一版功能

选中回复文字；新增、修改、删除批注；展示原文与批注对应关系；查看本次完整 user message；合并普通输入；一次发送；本地回看历史。

草稿/已发送仅用于防重复提交与历史归档，不代表模型已正确执行。

## 暂不纳入

持续约束管理、自动冲突裁决、任务解决状态、团队协作、云同步、自动 AI 改写、隐藏上下文注入、完整 agent 客户端重建。

遇到相互矛盾的用户文字，像正常 user message 一样交给原生 agent 处理；组装器不偷偷决定优先级。

## 用户可见与模型可见

| 内容 | 用户侧保存/展示 | 主动发给模型 |
| --- | --- | --- |
| 原文快照、消息位置、高亮 | 是 | 仅本次所需的引用文字 |
| 未选入本次发送的历史批注 | 是 | 否 |
| 本次批注原文 | 是 | 是 |
| 输入框补充文字 | 是 | 是，内容保持不变 |
| UUID、时间戳、UI 折叠状态 | 是或内部保存 | 否 |
| 已发送的组装文本 | 是 | 按原生会话历史机制保留 |
