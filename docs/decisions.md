# 决策记录

## 已确认

| 编号 | 决策 |
| --- | --- |
| D01 | 名称采用 TurnMargin · 旁注，公开开源仓库 |
| D02 | 流程为逐段批注、继续批注、补充普通输入、预览、一次发送、逐轮回看 |
| D03 | 三部分：批注界面、批注记录、反馈组装；反馈组装是重点 |

| D06 | 保持正常客户端的回复/执行体验，不加入额外解决状态工作流 |
| D07 | 目标是原生接入，不依赖 UI 抓取；优先简单、真实可用 |
| D08 | 记录固定任务/修改意图的实验，质量使用非劣效框架衡量 |
| D09 | 不提前承诺质量提升、token 降低或固定幅度；用实测决定 |
| D10 | 即使可能被原生产品替代，仍推进想法、harness 修改和扎实评测 |

## 当前建议，尚未验证

- Claude Code Mods 作为首个技术 spike；本机版本需要满足支持条件。
- 本地确定性反馈组装，不增加模型改写步骤。
- Promptfoo 负责实验运行/断言，自建小规模评分与配对统计。
- 原生选区、草稿组合与投递成功语义需要验证后再冻结实现。

## 明确撤回/不采用的早期建议

- 不将批注分为一次性约束与持续约束；没有自动持久规则机制。
- 不建立“agent 声称已处理 / 用户确认完成”的状态体系。
- 不由组装器自动裁决批注与输入之间的冲突。
- 不默认自建完整客户端，不把额外工具上下文当作普通用户消息。
